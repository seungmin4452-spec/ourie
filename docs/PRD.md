# PRD — Ourie

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | Ourie |
| 한 줄 정의 | 둘만 사용하는 커플 전용 추억 관리 PWA |
| 대상 사용자 | 연인 관계인 2인 (커플 단위 폐쇄형 서비스) |
| 플랫폼 | 모바일 웹 우선 PWA (홈 화면 추가, 오프라인 일부 지원) |

## 2. 배경 및 목표

기존의 오픈형 SNS(인스타그램 등)나 범용 캘린더/메모 앱은 "우리 둘만의 기록"이라는 프라이빗한 맥락을 담기 어렵다. Ourie는 커플 두 명만 접근 가능한 폐쇄형 공간에서 디데이, 추억, 여행 기록을 함께 쌓아가는 것을 목표로 한다.

**핵심 가치**
- **프라이버시**: 커플 2인 외에는 어떤 데이터도 노출되지 않음 (RLS 기반 격리)
- **함께 기록**: 두 사람이 같은 타임라인에 기여
- **감성적 경험**: 딱딱한 생산성 툴이 아닌, 감정을 담는 앱

## 3. 핵심 기능

### 3.1 커플 연결 (Couple Pairing)
- 최초 가입 시 개인 계정 생성 후, 초대 코드/링크를 통해 상대방과 1:1로 연결
- 연결 완료 시점부터 두 사람의 데이터가 하나의 `couple` 단위로 공유됨
- 연결 해제(이별/실수) 시나리오에 대한 정책 필요 (데이터 보존/삭제 여부는 정책 확정 필요)

**유저 스토리**
- 사용자로서, 초대 코드를 생성해 상대방에게 공유하고 싶다.
- 사용자로서, 상대방이 이미 다른 커플과 연결되어 있다면 연결 시도 시 명확한 에러를 보고 싶다.

### 3.2 디데이 (D-day)
- 사귄 날짜(기념일) 등록 → 자동으로 D+N / D-N 계산 및 표시
- 여러 개의 기념일(처음 만난 날, 고백일, 결혼기념일 등) 등록 가능
- 홈 화면에 다음 다가오는 디데이 강조 표시

**유저 스토리**
- 사용자로서, 기념일을 등록하면 오늘이 며칠째인지 자동으로 보고 싶다.
- 사용자로서, 다가오는 기념일을 놓치지 않도록 알림을 받고 싶다.

**알림 정책** (구현 완료, 상세는 `ARCHITECTURE.md` §6.1)
- 하루 한 번, KST 오전 8시에 "오늘 며칠째"를 보낸다
- 100일 단위(100·200·…, 1000일 단위는 더 특별하게)와 주년에는 축하 문구로 바뀐다
- 마일스톤 3일 전에는 미리 알린다
- 알림은 커플 공유가 아니라 개인별 설정이며, `/anniversaries`에서 켜고 끈다
- iOS는 홈 화면에 추가한 앱에서만 받을 수 있다

### 3.2.1 콕 찌르기 (Poke)
- 홈 위젯의 버튼을 누르면 커플 상대방의 기기에 즉시 알림이 간다
- 기본으로 주는 말은 네 가지: "보고싶어" / "카톡 확인해줘" / "전화해줘" / "뭐해?"

**유저 스토리**
- 사용자로서, 보고 싶다는 말을 앱을 열게 하지 않고 바로 전하고 싶다.
- 사용자로서, 상대가 답이 없을 때 카톡이나 전화를 확인해달라고 가볍게 알리고 싶다.
- 사용자로서, 원하지 않으면 이 알림을 안 받을 수 있어야 한다.

**정책** (구현 완료, 상세는 `ARCHITECTURE.md` §6.2)
- **받는 쪽이 동의해야 간다.** 기본값은 꺼짐이고, 매일 디데이 알림과 별개의 스위치다 (이것만은 내가 아니라 상대방이 내 기기를 울리기 때문)
- 상대가 켜지 않았으면 버튼이 눌리기 전부터 잠기고 이유가 보인다
- 같은 말은 1초에 한 번까지. 하루 총량 제한은 없다
- 자유 입력은 지원하지 않는다 (문구 검증·페이로드 크기 문제를 지금 떠안지 않기 위해)
- iOS는 홈 화면에 추가한 앱에서만 받을 수 있다 (디데이 알림과 같은 제약)

### 3.3 추억 타임라인 (Memory Timeline)
- 텍스트 + 사진(복수)으로 구성된 "추억" 게시물을 시간순으로 기록
- 날짜, 위치(선택), 태그 등 메타데이터 첨부
- 두 사람 중 누구나 작성/수정 가능, 작성자 표시

**유저 스토리**
- 사용자로서, 오늘 있었던 일을 사진과 함께 기록하고 싶다.
- 사용자로서, 지난 추억을 날짜순으로 스크롤하며 다시 보고 싶다.

### 3.4 스크래치 지도 (구현 완료, 상세는 `src/features/travel/README.md`)

커플이 고른 **사진을 대한민국 지도 모양으로 깔고, 아직 안 다녀온 시군구만 코팅으로 덮는다.**
다녀온 곳을 긁으면 그 조각의 사진이 드러나고, 191곳을 다 긁으면 사진이 온전히 보인다.

- 홈 위젯이다 (별도 탭이 아니다). 위젯을 붙이고 떼는 규칙은 다른 위젯과 같다
- 전국 지도에서 **시도를 누르면** 그 안이 크게 열리고, 거기서 **시군구를 눌러 긁는다**
- 배경 사진과 긁은 지역 모두 **커플 공용**이다 — 한쪽이 긁으면 상대 홈에서도 벗겨져 있다
- 울릉도·독도는 확대 삽입도로 넣는다 (실제 좌표에 넣으면 화면에서 1픽셀 미만)

**유저 스토리**
- 사용자로서, 우리가 함께 가본 곳이 쌓여가는 걸 한눈에 보고 싶다.
- 사용자로서, 우리 사진이 조금씩 드러나는 재미로 기록하고 싶다.

**결정 사항**
- **핀이 아니라 구역이다.** 좌표를 저장했다가 매번 구역을 역산하면 경계에 걸친 지점 하나
  때문에 칠해진 지역이 바뀐다. `travel_visits`는 시군구 코드를 그대로 저장한다
- **긁는 단위는 시·군(191곳)**이다. 시도(16곳)로는 금방 끝나서 사진이 너무 빨리 드러나고,
  자치구까지 쪼개면(256곳) "부산 해운대구"처럼 여행 기록에 안 맞게 잘아진다. 그래서 구는
  상위로 합치되 **서울만 예외**다 — 서울은 그만큼 넓어서 구 단위가 실제로 의미가 있다.
  군(기장·달성·군위·강화·옹진·울주)은 시내와 전혀 다른 여행지라 합치지 않는다
- **행정구역은 바뀐다** — 2026년 7월 광주·전남 통합으로 시도가 17→16이 됐다. 코드
  허용 목록을 DB에 박지 않고, 화면이 모르는 코드를 무시하는 쪽으로 설계했다

### 3.4.1 여행 핀 지도 (미구현)
- 추억에 위치 정보가 있는 경우, 지도 위에 핀으로 시각화
- 지도 위 핀 클릭 시 관련 추억으로 이동
- 스크래치 지도와 다른 화면이다. `travel_places` 테이블이 이 용도로 남아 있고,
  `travel_visits.memory_id`가 둘을 잇는 자리다 (추억 타임라인 §3.3 이후)

### 3.5 커스터마이징 (Customization)
- 앱 테마 컬러, 커플 닉네임, 대표 사진(커버), 위젯 배치 등 개인화 요소
- 커플 단위로 공유되는 설정(테마 등)과 개인 단위 설정(알림 등) 구분 필요

**유저 스토리**
- 사용자로서, 우리 커플만의 테마 색상을 지정하고 싶다.
