# UI GUIDE — Ourie

## 1. 톤앤매너

Ourie는 생산성 툴이 아니라 "감정을 기록하는 공간"이다. UI는 다음 원칙을 따른다.

- **심플함**: 색을 최소화한 화이트(라이트) / 다크 2가지 모드만 지원. 파스텔·브랜드 컬러 대신 Astryx neutral 팔레트 그대로 사용
- **둘만의 공간감**: 폐쇄형 서비스라는 특성을 살려 아늑하고 프라이빗한 느낌
- **사진이 주인공**: 텍스트보다 사진/추억이 시각적으로 강조되는 레이아웃
- **가벼움**: 모바일 PWA 특성상 로딩이 빠르고 인터랙션이 가벼워야 함

## 2. 컬러 팔레트

화이트(라이트) / 다크 2가지 모드만 지원하며, 기본은 라이트 모드다. 별도 브랜드 컬러 없이 Astryx `neutralTheme`의 기본 팔레트를 그대로 사용한다 (`src/app/theme.ts`의 `ourieTheme`은 `radius-container`만 오버라이드).

- `src/app/providers.tsx`에서 `<Theme theme={ourieTheme} mode="light">`로 기본 모드를 라이트로 고정했다. 다크 모드는 토큰 상 이미 지원되므로, 수동 전환 토글을 만들 때 `mode` prop만 바꿔주면 된다 (§7 참고).
- 색상을 바꿀 땐 컴포넌트에 하드코딩하지 말고 `theme.ts`의 `tokens`를 수정할 것.
- 커플별 `theme_color`(`DATABASE.md` 참고)를 다시 도입하고 싶다면 `ourieTheme`을 `extends`하는 별도 `<Theme>`로 해당 서브트리를 감싸 `--color-accent`를 오버라이드하는 방식을 쓴다 (현재는 요구사항에서 제외됨).
- Tailwind 유틸리티는 Astryx의 `tailwind-theme.css` 브리지를 통해 토큰과 동기화된다 (`bg-surface`, `text-primary`, `text-secondary`, `bg-accent-bg`, `text-accent` 등). 임의 hex/px 값을 className에 직접 넣지 않는다.

## 3. 타이포그래피

| 용도 | 크기 (모바일 기준) | 굵기 |
|---|---|---|
| 페이지 타이틀 (예: "우리의 타임라인") | 24px | Medium/Semibold |
| 섹션 헤더 | 18px | Medium |
| 본문 | 15px | Regular |
| 보조/캡션 (날짜, 위치 등) | 13px | Regular |
| 디데이 숫자 강조 | 32px~40px | Bold |

- 시스템 폰트 우선 (`system-ui` 등) 사용으로 로딩 비용 최소화, 추후 감성적인 커스텀 폰트(예: 손글씨 계열) 도입 검토 가능

## 4. 레이아웃 원칙

- **모바일 우선**: 최대 폭 480~560px 정도의 단일 컬럼 레이아웃을 기본으로, 데스크톱에서는 중앙 정렬
- **하단 탭 내비게이션**: 홈 / 타임라인 / 지도 / 설정 4개 내외로 구성 (엄지 접근성 고려)
- **여백**: 감성적인 느낌을 위해 밀도를 낮추고 여백을 넉넉히 사용 (카드 간 간격 16px 이상)
- **안전 영역 대응**: PWA standalone 모드에서 iOS 노치/홈 인디케이터 영역(`env(safe-area-inset-*)`) 고려

## 5. 핵심 화면별 가이드

### 5.1 홈
- 상단: 커플 대표 사진/닉네임 + 가장 가까운 디데이 큰 숫자로 강조
- 그 아래: 최근 추억 미리보기 카드 (2~3개)

구현 상태 (`src/features/couple/pages/HomePage.tsx`):
- 디데이 강조는 `DdayHighlight` (Astryx `Card variant="muted"` + `Heading type="display-2"`). 숫자 크기는 §3의 32~40px를 px로 박지 않고 display 타입 스케일 토큰을 쓴다
- 어떤 기념일을 크게 띄울지는 `pickHighlight` — 커플이 기념일 화면의 라디오로 **직접 고른 것**(`is_primary`)이 우선이고, 고른 적이 없으면 가장 가까이 다가온 것으로 떨어진다. 매일 오는 디데이 알림도 같은 선택을 따른다 (`notification/baseAnniversary.ts`). 기준일이 이미 지났으면 "함께한 지 N일째"(한국식으로 기준일이 1일째)를 아래에 덧붙인다
- 기념일이 하나도 없으면 `EmptyState`로 `/anniversaries` 등록을 유도한다
- 최근 추억 영역은 타임라인(PRD §3.3) 구현 전까지 `EmptyState` 자리표시자다

### 5.2 추억 타임라인
- 날짜 그룹핑된 세로 스크롤 리스트
- 카드형: 사진(대표 1장 또는 그리드) + 날짜 + 짧은 텍스트 미리보기
- 작성자(둘 중 누구) 구분은 은은한 뱃지/아이콘으로만 표시 (과도한 구분 지양 — "우리"라는 감각 유지)

### 5.3 지도 위젯 ("우리가 다녀온 곳" · "사진으로 채우는 지도")

둘은 같은 지도(`RegionMap`)를 쓴다. 아래 규칙은 양쪽 모두에 해당하고, 다른 점은 맨 끝에 적었다.

구현 상태 (`src/features/travel/`):
- 지도는 Astryx에 없어 SVG를 직접 그린다. 색은 전부 토큰 기반 유틸리티다 —
  코팅은 `fill-skeleton`("아직 안 드러난 자리"), 경계선은 `stroke-border`
- **코팅과 바탕은 확실히 갈려야 한다.** 처음에 사진 없을 때의 바탕을 `fill-muted`(#f1f1f1)로
  뒀더니 코팅(#ebebeb)과 거의 같은 색이라 긁어도 아무 반응이 없어 보였다. 지금은
  `fill-secondary`(라이트 중간 회색 / 다크 밝은 회색)라 양쪽 모드에서 모두 갈린다
- **선 굵기가 지금 누르는 단위를 말한다.** 전국 지도에서는 시도가 굵고(1.4) 시군구가
  가늘다(0.5). 누르는 것은 굵은 쪽이다
- **터치 타겟**(§8): 도형이 44px보다 작게 그려지는 구역은 가운데에 투명한 원을 얹어
  탭 목표를 넓힌다. 문턱은 현재 viewBox 폭에서 환산하므로, 상세로 들어가면 도움이 필요한
  구역도 자연히 줄어든다
- **키보드 포커스**: 크롬은 SVG 도형에 포커스가 가면 도형이 아니라 경계 상자에 네모를
  그린다. `outline-none`으로 끄고 도형을 따라가는 선을 직접 그린다. 마우스 클릭에는 안
  뜨도록 `:focus-visible`을 요소에 직접 물어본다
- **시군구 이름은 상세 화면에만 적는다.** 전국 지도에 191개를 적으면 지도가 아니라 글자
  더미가 된다. 글자 크기는 뷰박스가 아니라 **화면**에서 일정해야 한다 — 상세 프레임이
  서울(47)부터 경북(315)까지 여섯 배 넘게 차이 나서, 고정 값을 쓰면 어떤 시도에서는
  깨알같고 어떤 시도에서는 화면을 뒤덮는다. 이름이 도형보다 넓으면 라벨을 접는다
- **라벨은 코팅 위에도 드러난 사진 위에도 읽혀야 한다.** 배경색(`stroke-body`)으로 테두리를
  두르고 `paint-order: stroke`로 글자 뒤에 깐다
- **삽입도**(울릉도·독도 / 서해 5도)는 상자와 이름표로 "실제 축척이 아님"을 드러낸다.
  상세 화면에 넣을지는 데이터가 정한다 — 상자가 본토에서 멀면 프레임이 넓어져 그 시도의
  시군구가 못 누를 만큼 작아지기 때문이다 (`regions.ts`의 `showInDetail`)
- 시도 상세는 Astryx `Dialog`(§6 참고). 아직 Bottom Sheet는 만들지 않았다
- **두 위젯이 갈리는 곳은 "시군구를 눌렀을 때"뿐이다.** 스크래치는 누르는 즉시 긁히고
  (한 번 더 누르면 되돌아간다), 사진 지도는 **고르기만 하고** 무엇을 할지는 지도 아래
  버튼에서 정한다("사진 고르기 / 바꾸기 / 빼기"). 누르자마자 사진첩이 열리면 지도를 훑다
  손가락이 스친 것만으로 창이 뜨고, 이미 걸린 사진을 빼는 길도 사라진다. 지금 고른 구역은
  포커스와 같은 굵은 선(`stroke-accent-bg`)으로 표시해 아래 버튼과 이어준다

### 5.3.1 소원권 위젯

구현 상태 (`src/features/wish/`):
- **위젯이 답하는 질문은 하나다 — "지금 각자 몇 장 남았나".** 그래서 본문은 두 사람의
  막대 두 개 + 최근 소원 한 줄 + 버튼 하나가 전부다. 무엇을 부탁했는지, 장수를 몇 장으로
  할지는 전부 `WishDialog`로 밀어냈다. 홈 카드가 스크롤을 먹기 시작하면 그건 위젯이 아니라
  화면이다
- 한 사람의 현황은 `WishMeter` 한 조각이고 위젯과 다이얼로그가 **같은 것**을 쓴다. 그래야
  다이얼로그를 열어도 "위젯에서 본 그 숫자"라는 감각이 유지된다
- 막대(`ProgressBar`)는 **남은** 장수를 그린다 — 가득 찬 막대가 아직 하나도 안 쓴 상태이고
  쓸수록 줄어든다. 위 질문에 맞춘 방향이다. 다 쓰면 `variant="neutral"`로 죽는다
- 숫자는 `hasTabularNumbers`. 두 사람의 줄이 위아래로 놓이므로 자릿수가 흔들리면 안 된다
- 다 쓴 사람도 버튼을 누를 수 있다. 그때 가장 필요한 일이 "무엇에 썼는지 보고 하나 지우는
  것"인데 그 문이 이 버튼뿐이라, 잠그는 대신 라벨만 "쓴 소원권 보기"로 바뀐다
- 다이얼로그는 현황 막대를 맨 위에 두고 그 아래에 목록·폼·장수를 쌓는다. 셋이 같은 숫자를
  움직이므로(쓰면 줄고, 지우면 돌아오고, 장수를 고치면 다시 계산된다) 화면을 나누면 그
  인과가 화면 전환 뒤로 숨는다. 고치기는 목록이 아니라 아래 폼에서 일어난다
  (`PokePresetDialog`와 같은 방식 — 고치는 줄이 목록에서 선택 상태로 남는다)
- 장수 설정(`WishTotalForm`)은 **막대 바로 밑**에 접어둔다. 한때 다이얼로그 맨 아래에
  뒀는데 목록과 작성 폼을 다 지나쳐야 나와서 이런 게 있는 줄도 모르고 지나쳤다. 바꾸는
  숫자 옆에 있어야 찾는다 — "몇 장이지?"를 묻는 자리가 "몇 장으로 할까?"를 묻는 자리다.
  접어두는 것은 그대로다 (펼쳐두면 소원을 쓰러 올 때마다 숫자 두 칸이 길을 막는다)
- 내 장수만이 아니라 **상대의 장수도 여기서 정한다.** 소원권은 "몇 장씩 갖자"는 둘 사이의
  약속이라, 각자 자기 것만 정할 수 있으면 그건 약속이 아니라 자기 신고가 된다 (RLS도 커플
  범위)
- 장수는 숫자 입력칸이 아니라 **−/+ 버튼**으로 센다 (`WishTotalStepper`). 여기서 바뀌는
  값은 대개 한두 장이고, 모바일에서 숫자칸을 누르면 키보드가 올라와 다이얼로그의 절반을
  덮는다. 눌러서 세는 쪽이 "한 장 더 준다"는 행동에도 가깝다. 숫자 자리는 폭을 고정한다 —
  5장과 12장 사이를 오갈 때 버튼이 흔들리면 연달아 누를 수 없다
- 아래로는 **이미 쓴 장수**가 바닥이라 그 아래로는 버튼이 잠긴다. DB도 같은 것을 막지만
  (`check_wish_total`), 눌러보고 에러를 보는 것보다 잠기는 편이 낫다

### 5.3.2 마이페이지 (`/me`)

구현 상태 (`src/features/me/`):
- 지금은 **알림 설정 하나를 위한 화면**이다. 홈 하단의 "마이페이지" 버튼으로 들어간다
- 만든 이유는 스위치가 흩어져 있어서가 아니라, **그 위젯을 홈에 올리지 않은 사람에게는
  켤 자리가 아예 없었기** 때문이다. 매일 디데이 알림은 `/anniversaries` 아래, 상대방이
  보내는 알림은 콕 찌르기 위젯 안에만 있었는데, 소원권 알림이 같은 동의를 쓰기 시작하면서
  그게 실제 구멍이 됐다
- **콕 찌르기 위젯에는 이제 스위치가 없다.** 위젯 하나에 얹혀 있을 값이 아니었다 —
  소원권 알림까지 함께 가르는 데다, 그 위젯을 홈에 올리지 않으면 켤 자리가 없었다.
  `/anniversaries`의 디데이 스위치는 그대로 둔다 (기념일을 막 등록한 자리에서 "매일
  알려줄까요?"를 만나는 맥락은 여전히 유효하고, 같은 컴포넌트라 어느 쪽에서 켜도 똑같다)
- 스위치가 둘인 이유는 성격이 달라서다 — 매일 정해진 시각에 오는 것과, 상대가 눌러서
  보내는 것. 디데이는 받고 싶지만 상대가 내 폰을 울리는 건 싫을 수 있다
- **둘 사이는 `Divider`로 가른다.** 디데이 스위치는 아래에 미리보기 세 줄을 달고 나오는데,
  선이 없으면 그 줄들이 다음 스위치의 설명처럼 읽힌다 (둘 사이 간격과 스위치·설명 사이
  간격이 같아서 무엇이 무엇에 속하는지 알 수가 없었다)
- 디데이 스위치의 "**위에서 고른** 기념일" 문구는 목록이 같은 화면에 있을 때만 쓸 수 있다.
  마이페이지에는 목록이 없으므로 `hasAnniversaryList={false}`로 문구를 바꾼다 — 없는 것을
  가리키면 안내가 아니라 수수께끼가 된다
- **`Switch`에는 `labelPosition="start"`를 반드시 함께 준다.** `labelSpacing="spread"`만
  주면 기본값(`labelPosition="end"`)이 스위치를 앞에 놓고 라벨을 뒤로 보내는데, spread가
  그 둘을 양 끝으로 밀어내서 **화면 왼쪽 끝에 토글만 덩그러니, 글자는 오른쪽 끝에 붙어**
  오른쪽 정렬처럼 보인다. 아래 설명·미리보기는 왼쪽 정렬이라 아무것도 맞지 않는다.
  설정 줄의 기본형은 글자가 왼쪽, 스위치가 오른쪽이다 (실제로 겪었던 문제)

### 5.3.3 첫 실행 알림 안내 (`NotificationPromptDialog`)

- 앱에 처음 들어오면 홈에서 **한 번** 뜬다. 스위치를 찾아 들어가야만 켤 수 있을 때는
  아무도 켜지 않았는데, 이 앱의 알림은 성가신 마케팅이 아니라 **기능 그 자체**다 —
  디데이도 콕 찌르기도 소원권도 알림으로만 닿는다
- **한 번만 묻는 것이 제일 중요한 규칙이다.** 그래서 "켰는가"가 아니라 "물어봤는가"를
  기기(`localStorage`)에 남긴다. 바깥을 눌러 닫아도, 권한 창에서 거절해도 물어본 것으로
  친다 (거절 후에는 브라우저가 권한 창을 다시 띄워주지도 않는다). 마음이 바뀌면
  마이페이지에서 켠다
- 알림을 켤 수 없는 상태(`unsupported` / `needs-install` / `blocked`)에서는 뜨지 않는다.
  할 수 없는 일을 권하면 안내가 아니라 막다른 길이다
- 여기서는 **두 종류를 한 번에** 켠다. 묻는 것은 "알림을 받겠는가" 하나이고, 종류별로 또
  물으면 같은 질문을 두 번 하는 셈이다. 나눠 정하고 싶은 사람을 위해 마이페이지에 스위치가
  둘 있다
- 머리에는 두 사람의 프로필 사진을 `AvatarGroup`으로 겹쳐 둔다. 이 앱에서 "나"는 언제나
  둘 중 하나라, 내 얼굴만 덩그러니 있는 마이페이지는 이 앱의 화면 같지 않다

### 5.4 커스터마이징/설정
- 테마 컬러는 프리셋 몇 가지 제공 후 필요시 커스텀 컬러피커 (초기엔 프리셋만으로 충분)
- 설정 항목은 리스트형 UI로 단순하게 구성

## 6. 컴포넌트 가이드
UI는 Astryx(`@astryxdesign/core`)로 통일한다. 새 컴포넌트가 필요하면 직접 만들기 전에 `npx astryx component <이름>` / `npx astryx search "<키워드>"`로 먼저 확인한다.

- **Button**: Astryx `Button` — `variant`: primary(강조색 채움) / secondary / ghost / destructive
- **입력 필드**: Astryx `TextInput` (label/description/status 내장, 별도 Label 불필요)
- **Card**: Astryx `Card` — radius는 테마의 `--radius-container`(16px)를 따름
- **Badge**: 작성자 표시, 태그 표시용 (타임라인 구현 시 도입 — PRD §3.3)
- **Toast**: 저장 완료/실패 등 비차단 피드백 (`useToast`) — 폼 필드 자체 검증 에러는 `TextInput`의 `status` prop 사용
- **지도 핀 상세 / 사진 확대**: Astryx에 Bottom Sheet 컴포넌트가 없음. `Dialog`를 하단 고정형으로 커스텀 스타일링해서 사용 (핀 지도 §5.3 하단 구현 시 결정)
- **지도 위젯 상세**: 기본 `Dialog`를 그대로 쓴다 (`RegionScratchDialog`, `RegionPhotoDialog`). 하단 시트가 아닌 이유는 내용이 지도 한 장이라 화면 가운데가 더 잘 보이기 때문

## 7. 다크모드
- 시스템 설정(`prefers-color-scheme`)을 따르지 않고 기본값을 라이트 모드로 고정
- 사용자가 화면 우측 상단의 토글 버튼(`ColorModeToggle`)으로 라이트/다크를 직접 전환할 수 있다. 선택값은 `localStorage`(`ourie-color-mode`)에 저장되어 재방문 시에도 유지된다 (`src/app/ColorModeProvider.tsx`)
- 구현 시 `src/index.css`에 `color-scheme`을 직접 선언하지 않는다 — Astryx `reset.css`가 `Theme`의 `mode`를 보고 알아서 처리하며, 직접 선언하면 이 동작을 깨뜨린다 (`CLAUDE.md` 참고)

## 8. 접근성
- 이미지에는 대체 텍스트(간단한 설명) 입력 권장 (필수는 아니되 UX상 유도)
- 터치 타겟 최소 44x44px 확보
- 텍스트 대비 WCAG AA 기준 참고

## 9. 미결 사항
- 커스텀 폰트 도입 여부 (현재 `theme.ts`는 system-ui 사용)
- 커플별 `theme_color` 커스터마이징 재도입 여부 (현재 요구사항에서 제외, §2 참고)
- Bottom Sheet 대체 컴포넌트(Astryx Dialog 커스텀) 구체 구현 미착수
- 라이트/다크 토글 위치가 현재는 임시로 우측 상단 고정 버튼. 설정 화면이 생기면 그쪽으로 옮길지 검토
